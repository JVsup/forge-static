Description

A server mod for SPT 4.0+ that randomizes raid duration on every raid start, forcing you to actually check the timer and adapt their strategy accordingly.

Got a long raid? Pace yourself. Loot, explore, but don’t forget to check your doors and corners. That’s how they get you, kid.

Got a short raid? Forget about looting and haul ass out of there.

Installation

Like the other mods. You extract the contents of the 7z archive into your main SPT folder.

That’s it.

Configuration

Edit config.json to adjust the behaviour:

"MaxVariancePercent"

Maximum deviation from the map’s base raid time, as a percentage.
A value of 20 means the raid time can vary by up to +-20% of the base duration.

"Bias"

Controls the probability of getting a longer or shorter raid. Lower values means chance leans towards shorter raids. 0 is shorter raids only. 10 is effectively only longer raids.

"MinimumRaidTimeMinutes"

Hard floor in minutes. The randomized time will never go below this value regardless of variance.

Compatibility

SPT 4.0.0+

I have not tested with Fika, and I don’t intend to.

Changelog

1.1.0

  • Complete rewrite of the per-raid hook. Previously used IOnBeforeEventRequestData, which is dead code in SPT and never fires. Mod was silently applying the same time every raid until server restart.
  • Now hooks MatchController.ConfigureOfflineRaid via Harmony postfix, which fires correctly on every raid start.
  • Replaced Console.WriteLine with ISptLogger (injected).
  • Replaced ServiceLocator with proper DI injection throughout.
  • Config reworked: dropped AllowIncrease and AllowDecrease in favor of a single Bias float using an odds-ratio model.
  • Config file is now resolved relative to the DLL, folder can be renamed freely.
  • Server console now logs map name, delta, and final raid time on each raid start.
