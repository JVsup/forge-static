Description Versions 19

Keep Starting Gear

The cure for gear fear. Protect your loadout. Die without consequences.

What It Does

Keep Starting Gear saves your equipment when you enter a raid and restores it if you die. Extract successfully?

Keep your loot. Die? Get your starting gear back.

No Run-Through penalty. No exploits. Just protection.

30 Seconds to Understand

Enter Raid → Gear auto-saved → Die → Gear restored → Extract → Keep your loot

Key Features

  • Automatic Snapshots – Gear saved at raid start (default) or manually via keybind
  • Full Restoration – Durability, ammo counts, medical uses, armor plates, all preserved
  • No Penalties – Server-side restoration bypasses “Run-Through” status
  • Slot Control – Protect exactly what you want, 16 individual slot toggles
  • Modded Items – Works with any custom weapons, armor, and equipment
  • SVM Compatible – Works with Server Value Modifier (disable Softcore Mode & Safe Exit)

Quick Start

Extract the archive directly into your SPT root folder (where SPT.Server.exe is located) and merge when prompted.

Both client and server components are included and pre-configured.

After install you should have:

  • Client: BepInEx/plugins/Blackhorse311-KeepStartingGear/Blackhorse311.KeepStartingGear.dll
  • Server: SPT/user/mods/Blackhorse311-KeepStartingGear/Blackhorse311.KeepStartingGear.Server.dll

Default Behavior

  1. Enter raid – green notification confirms snapshot
  2. Die – gear automatically restored
  3. Extract – snapshot cleared, loot kept

Playstyle Presets

  • Casual (Default) – Maximum protection, zero hassle. Auto-snapshot at raid start, all slots protected.
  • Hardcore – Manual snapshots only. Exclude Found-in-Raid and insured items. Risk what you find, protect what you bring.
  • Custom – Fine-tune every setting: snapshot mode, individual slots, keybinds, notifications.

Configuration

Press F12 in-game to access settings:

  • Snapshot Mode (Auto Only) – Auto / Auto+Manual / Manual
  • Individual Slots (All enabled) – 16 slots individually toggled
  • Protect FIR Items (off) – Exclude Found-in-Raid items from snapshots
  • Exclude Insured (off) – Let insurance handle insured items
  • Manual Keybind (Ctrl+Alt+F8) – Keybind for manual snapshots
  • Notifications (on) – On-screen snapshot/restore messages

Compatibility

  • SPT 4.0.x – Supported, tested on 4.0.12
  • SVM – Compatible, disable Softcore Mode & Safe Exit
  • FIKA – Not compatible, single-player only
  • Custom Items – Full support, works with any modded gear

Fixed - SVM Compatibility and Scabbard Preservation

This release fixes gear not restoring on death when SVM is installed (GitHub #20), and melee weapons being deleted from non-managed Scabbard slots.

SVM Restoration Failure (CRITICAL)

Problem: When SVM is installed, it replaces MatchCallbacks via dependency injection, preventing RaidEndInterceptor from running. The fallback restoration in DeleteInventory was too late in SPT’s pipeline. By the time it ran, SetInventory had already copied the death-state inventory to the server profile.

Symptoms:

  • Only Pockets restored on death (because Pockets container is always preserved)
  • All other gear lost despite snapshot being taken
  • Only occurs when SVM is installed

Fix: Override SetInventory in CustomInRaidHelper to restore snapshot items into postRaidProfile BEFORE base.SetInventory copies them to the server profile. The snapshot file acts as coordination: if RaidEndInterceptor already ran, it deleted the file so SetInventory finds nothing. If SVM prevented it, the file still exists.

Scabbard Deletion on Death (MEDIUM)

Problem: Melee weapons were being deleted from non-managed Scabbard slots. In normal Tarkov, melee weapons are never lost on death.

Fix: Added Scabbard to always-preserved slots in DeleteNonManagedSlotItems.

Technical

  • New two-phase restoration: Phase 1 (SetInventory override) restores snapshot, Phase 2 (DeleteInventory override) handles selective deletion
  • Removed fallback TryRestore from DeleteInventory (was too late in the pipeline)
  • Added Constants.ScabbardSlot shared constant
  • 48 tests passing (10 serialization + 38 restoration algorithm)
  • All fixes are server-side only; client DLL version bumped but code unchanged

Important fix for pockets contents keeping their raid-end state instead of being restored from snapshot on death. Regression introduced in v2.0.5.

What’s Fixed

Issue Severity Symptom
Pockets contents not managed during restoration HIGH Medical items in pockets stay used, looted items stay
after death
Pockets death mechanics in partial deletion MEDIUM Pockets contents preserved when slot is unmanaged (should
be lost like normal death)

What Was Happening

Pockets Contents Skipped

The v2.0.5 fix correctly prevented the Pockets container from being deleted (which corrupts profiles), but it also skipped all Pockets contents from the removal phase. This meant items inside Pockets were never removed during restoration — snapshot items with original state were skipped as duplicates.

Example: You enter raid with a full Calok in your pockets. You use it mid-raid (2 charges remaining). You die. The mod should restore the full Calok from snapshot, but instead you keep the used one.

Fix: Separated container preservation from content management. Permanent containers (SecuredContainer, Pockets) are never deleted, but their contents are now properly removed and restored from snapshot. Added preservedManagedContainerIds set to track containers whose children should be seeded into the BFS removal queue.

Pockets Death Mechanics

In DeleteNonManagedSlotItems (partial death processing), Pockets was treated identically to SecuredContainer — both container and contents were always preserved. But in normal Tarkov, SecuredContainer contents survive death while Pockets contents are lost.

Fix: SecuredContainer preserves container + contents (normal Tarkov). Pockets preserves container but deletes contents when not managed (normal death behavior).

Technical Details

  • New pattern: preservedManagedContainerIds tracks permanent containers whose children enter the BFS removal queue
  • IsSlotManaged no longer special-cases SC/Pockets — content management is separate from container preservation

Critical fix for gear loss, secure container disappearing, and permanent pockets corruption reported by multiple users since v2.0.1.

What’s Fixed

Issue Severity Symptom
ThreadLocal cross-thread bug CRITICAL Total gear loss on death, secure container disappearing, gear on
hideout mannequin
Pockets not protected from deletion HIGH Permanent profile corruption — pockets become “empty rig slot with
no slots“
Client DLL version mismatch LOW Client reported v2.0.4 while server reported v2.0.5

What Was Happening

ThreadLocal State Bug

SnapshotRestorationState used ThreadLocal<bool> to communicate between RaidEndInterceptor (restores inventory) and CustomInRaidHelper.DeleteInventory (must skip deletion). If SPT dispatched these on different threads — which it can — the restoration flag was invisible to the deletion code, causing it to wipe all equipment.

Fix: Replaced ThreadLocal with ConcurrentDictionary<string, RestorationData> keyed by session ID.

Pockets Corruption

Only SecuredContainer was in the always-preserved slots list. Pockets is also a permanent fixture that should never be deleted. When Pockets was in a non-managed slot, it was deleted entirely — not just its contents — permanently corrupting the profile.

Fix: Added Pockets to alwaysPreservedSlots and added explicit protection in both deletion paths.

Installation

  1. Download Blackhorse311-KeepStartingGear-v2.0.5.7z
  2. Extract directly into your SPT root folder (where SPT.Server.exe is)
  3. When prompted, merge/overwrite folders

[SPT Root]/ ├── BepInEx/plugins/Blackhorse311-KeepStartingGear/ │ └── Blackhorse311.KeepStartingGear.dll ← Client └── SPT/user/mods/Blackhorse311-KeepStartingGear/ └── Blackhorse311.KeepStartingGear.Server.dll ← Server

Technical Details

  • Replaced ThreadLocal<bool>, ThreadLocal<HashSet<string>?>, ThreadLocal<int> with single ConcurrentDictionary<string, RestorationData>
  • New API: MarkRestored(), TryConsume(), Clear() — all keyed by session ID
  • Added Constants.PocketsSlot shared constant
  • 3 new unit tests for Pockets protection (44 tests total)
  • All fixes are server-side restoration logic; client DLL rebuilt for version consistency

What’s Fixed

Critical Bug Fix: Secure containers (and other non-managed slots) were being deleted when they should have been preserved.

The Problem

When users set “Restore Secure Container to Snapshot” to false (meaning they wanted normal Tarkov behavior where secure container contents are always kept), the secure container was being deleted entirely on death instead of being preserved.

This also affected users running mods like SVM (Server Value Modifier) that route through a different code path.

The Fix

Synchronized the slot preservation logic between both restoration code paths (RaidEndInterceptor.cs and CustomInRaidHelper.cs). Now:

  • Enabled slots → Items removed and restored from snapshot
  • Disabled slots → Items preserved (normal Tarkov behavior)
  • Empty slots at snapshot time → Looted items removed on death
