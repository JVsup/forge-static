BotMind — Smarter bots. On-demand medics.

Three AI modules in one package: intelligent Looting, objective-based Questing, and the MedicBuddy on-demand medical team.

How It Works:

Looting: Bots scan area → Find valuable loot → Navigate → Pick up items Questing: Bots get objectives → Navigate map → Explore → Extract MedicBuddy: Press LCtrl+LAlt+F10 → Team spawns → Medic heals you → Team retreats

Key Features

Intelligent Looting — Bots loot corpses, containers, and loose items based on value. Throttled to prevent hoover behavior (max 3 targets per 2 minutes, 15s cooldown between targets). Objective Questing — PMC and Scav bots pursue objectives, explore areas, and extract. Natural pauses between objectives. Raiders, Rogues, and boss bots are excluded. MedicBuddy — Summon a friendly medical team with one keypress. Full healing: HP, bleeds, fractures, destroyed limbs. Voice Lines — 60 voice lines (EN/RU) for immersive medic interactions. CCP Rally Points — Press Y to direct your medical team to a specific treatment location. Medic Promotion — If the medic dies, a shooter gets promoted automatically. SAIN Integration — Optional combat awareness and extraction support. Works fully without SAIN too. Configurable Combat Alert — Control how long bots fight before returning to objectives (default 15s, adjustable 10-120s in F12). SAIN BotMind Preset — Optional SAIN config preset for faster enemy detection and more aggressive combat.

MedicBuddy Controls

LCtrl+LAlt+F10 — Summon the medical team Y — Set a Casualty Collection Point (CCP) at your position

How MedicBuddy works:

  1. Press LCtrl+LAlt+F10 to summon the medical team
  2. A medic and shooter escorts spawn and navigate to your position
  3. Press Y to set a CCP rally point where you want treatment
  4. The team establishes a defensive perimeter
  5. The medic heals all injuries (HP, bleeds, fractures, destroyed limbs)
  6. After treatment, the team retreats and despawns

Tips:

  • Use open areas for your CCP — tight corridors cause navigation issues
  • Shooter escorts engage hostile bots during treatment
  • 5-minute cooldown between summons (configurable)
  • PMC raids only by default (configurable)
  • You must be injured and have no medical equipment to call the team

SAIN BotMind Preset (Optional)

BotMind includes an optional SAIN configuration preset that tunes bot detection and aggression. Without it, SAIN’s default settings can cause bots to walk past enemies before engaging.

What it changes (compared to SAIN “hard” difficulty):

  • GainSightCoef: 1.0 → 1.5 (50% faster visual target acquisition)
  • AggressionCoef: 1.0 → 1.3 (30% more aggressive combat decisions)
  • HearingDistanceCoef: 1.0 → 1.15 (15% better hearing range)
  • VisibleDistCoef: 1.0 → 1.1 (10% further vision range)

How to activate:

  1. Preset auto-installs to BepInEx/plugins/SAIN/Presets/BotMind/ when you extract the mod
  2. In-game, press F6 to open the SAIN GUI
  3. Select “BotMind” from the preset dropdown
  4. Changes take effect immediately

How to revert: Press F6 and select any other preset. Your original SAIN settings are never modified.

Configuration

Press F12 → Find “BotMind” → Adjust settings

General:

  • Enable Looting (default: on)
  • Enable Questing (default: on)
  • Enable MedicBuddy (default: on)
  • Combat Alert Duration (default: 15s) — How long bots fight after sensing an enemy before resuming objectives

Looting:

  • Search Radius (default: 35m, range: 10-200m)
  • Minimum Item Value (default: 5000 rubles)
  • Loot Corpses / Containers / Loose Items (all default: on)

Questing:

  • PMCs Do Quests (default: on)
  • Scavs Do Quests (default: off)
  • Quest Priority (default: 50)

MedicBuddy:

  • Summon Keybind (default: LCtrl+LAlt+F10)
  • Cooldown (default: 300s)
  • Team Size (default: 4, range: 2-6)
  • PMC Raids Only (default: on)
  • Rally Point Keybind (default: Y)
  • Enable Voice Lines (default: on)
  • Voice Volume (default: 80)
  • Escort Difficulty (default: 2/hard, range: 0-3)

Performance:

  • Max Bots Per Map (default: 0 = use game defaults, max: 31)
  • When MedicBuddy is enabled, team-size slots are auto-reserved so your medical team always has room to spawn.

Troubleshooting

  • Mod doesn’t work / strange behavior → Verify you are on SPT 4.0.12
  • MedicBuddy not responding → Check mod is enabled in F12. Check PMC-only setting if playing as Scav.
  • Medic getting stuck → Move to an open area and press Y to set a new CCP
  • Bots walking past enemies → Activate the BotMind SAIN preset (F6). Increase Combat Alert Duration in F12. Install Waypoints.
  • Bots freezing or getting stuck → Install Waypoints mod (DrakiaXYZ-Waypoints)
  • Bots looting too aggressively → Lower Search Radius (default 35m). Session limit is 3 targets per 2 minutes.
  • Bots standing still with questing on → Update to v1.6.0. Major fixes in v1.5.0 and v1.6.0.
  • Bots walking backwards → Update to v1.6.0. Fixed movement facing bug.
  • Raiders/Bloodhounds stuck on questing → Update to v1.6.0. Non-PMC/Scav bots are now excluded from questing.
  • Bots stuck looting a container → Update to v1.6.0. Added action-level timeout safety net.

What’s Changed

Three fixes for #10 reported by @DigitalBurns:

1. Container Loot Hang Fixed

Bots getting stuck in “Complete” looting state for 60s. Added action-level timeout (70s) in LootingLayer as a safety net when internal signals are lost, plus fixed a missing _target reset in LootCorpseLogic.

2. Raiders/Rogues No Longer Receive Questing Objectives

Raiders (brain name “PMC”, but WildSpawnType.pmcBot) and Rogues were falling through the PMC/Scav role guards in QuestingLayer and getting stuck on bad waypoints — especially on Woods. Added explicit role allowlist: only actual PMCs and Scavs get questing now.

3. Backwards Walking Fixed

All GoToPoint() calls were passing false for the lookToMovingDirection parameter, leaving EFT’s locomotion with no facing constraint. Changed to true across all movement calls. This is a one-time path hint (not the per-frame override removed in v1.2.0), so enemy detection remains unaffected.

v1.5.0 - Fix Questing Stuck at Spawn

What’s Changed

Major fix: Bots no longer get stuck at spawn when questing is enabled. Multiple users reported PMC bots standing still or returning to their spawn point with questing on. Root cause was 4 interacting bugs, all fixed in this release.

Bug Fixes

  • Questing layer stays active during cooldown — Previously, a 5-second gap between objectives let EFT’s default brain walk bots back to spawn. The layer now handles the pause internally so bots stay where they are.
  • Graduated waypoint generation — Old 50m minimum range frequently failed NavMesh validation on complex maps (Woods, Interchange). Now tries far→medium→close distance tiers (50-150m → 20-60m → 10-30m) so bots always find a reachable destination.
  • Progressive exploration — Explore waypoints now generate from the bot’s current position instead of a fixed point at spawn, so bots actually move outward across the map.
  • Combat alert duration reduced — Default reduced from 30s to 15s. The old value kept bots in perpetual “combat mode” on active maps, preventing questing entirely. Still configurable in F12.
  • Looting timeout log spam fixed — The timeout warning was firing every frame (producing 110,000+ spam lines in one session). Now logs once per timeout event.

Other Changes

  • POST_OBJECTIVE_COOLDOWN reduced from 5s to 3s for snappier objective transitions
  • Version strings synchronized to 1.5.0 across client, server, and plugin attribute
  • 20 new unit tests (191 total, all passing)

What’s New in v1.3.0

Looting reliability improvements and non-SAIN combat awareness. Bots no longer get stuck indefinitely on unreachable loot targets, and bots without SAIN now properly yield to combat.

Bug Fixes

  • Looting collider buffer increased from 64 to 256 — Prevents missing containers when loot-adding mods (Lots of Loot Redux, etc.) are installed. The previous buffer of 64 could silently truncate scan results on modded maps with dense loot.

  • Overall timeout (60s) added to all looting logic — Bots will no longer get stuck indefinitely on unreachable containers, corpses, or items. Container and corpse looting time out after 60 seconds; loose item pickup times out after 45 seconds.

  • Stuck detection added to container and corpse navigation — Bots abort after 5 consecutive movement checks with no distance progress (< 0.3m improvement). Catches cases where bots are pathing against walls or obstacles.

  • Non-SAIN combat fallback — Bots without SAIN now properly yield to combat via native EFT enemy detection (GoalEnemy, IsUnderFire). Previously, IsBotInCombat() returned float.MaxValue when SAIN wasn’t loaded, meaning bots would loot while being shot at.

  • 22 new unit tests for timeout logic, stuck detection, collider buffer bounds, and combat fallback (134 total)

What’s New (v1.1.0 + v1.1.1 + v1.2.0)

This is the first combined release since v1.0.0, covering three versions of improvements and bug fixes.

Features (v1.1.0)

  • Bot Limit Slider — BotLimitPatch + BotLimitManager with slot reservation for MedicBuddy escort teams
  • Escort Combat Awareness — DefendPerimeterLogic scans for threats using Physics.OverlapSphere, feeds CheckAndAddEnemy, and faces nearest enemy
  • Escort Difficulty Config — Configurable BotDifficulty (0–3, default: hard) for MedicBuddy escort bots
  • LootingBots Compatibility — Auto-detects LootingBots (me.skwizzy.lootingbots) and disables BotMind’s Looting module to avoid conflicts. MedicBuddy + Questing remain active.
  • 30 new unit tests — 112 total, all passing

Bug Fixes

v1.1.1 — Issue #1: Questing Idle/Stuck + PMC Non-Engagement

  • QuestManager.MarkCurrentObjectiveComplete() now calls UpdateObjectives() immediately instead of leaving a 5-second idle gap
  • Removed LookToMovingDirection() from GoToLocationLogic, ExploreAreaLogic, and ExtractLogic — these calls overrode EFT’s natural head-scanning, preventing LookSensor from detecting enemies, which meant SAIN combat never activated
  • QuestingLayer.IsActive() now updates immediately when idle (was throttled to 5s even with no objective)

v1.2.0 — Issues #2 & #3: Questing Failed/Standby States

  • Path reachability validation: Objective generation now validates a complete walkable path using NavMesh.CalculatePath() before accepting waypoints — not just checking that a position exists on NavMesh
  • Reduced snap tolerance: NavMesh.SamplePosition tolerance reduced from 20m to 5m to prevent wrong-floor/building snaps
  • Local exploration fallback: When no reachable long-range waypoints can be found, bots fall back to exploring locally (40m for PMCs, 30m for Scavs) instead of standing idle
  • F12 runtime toggle works: QuestingLayer is now always registered for both PMC and Scav brain types — the IsActive() method handles per-type filtering at runtime, so toggling PMCsDoQuests/ScavsDoQuests in F12 works without restart
  • Separate path failure counter: Path-to-target failures and movement-stuck detection now use independent counters, preventing premature failure declarations
  • Remaining LookToMovingDirection cleanup: Removed 5 more calls from FindItemLogic, PlaceItemLogic, LootContainerLogic, PickupItemLogic, and LootCorpseLogic
