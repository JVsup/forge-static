⚠️ Important cosmic disclaimer:

This mod does not, under any circumstances, boost performance, increase FPS, or imbue your server with the vigor of a caffeinated gazelle. It is only for people experiencing the specific memory issue described below.

If you install it “just in case”, the universe will not punish you, but I might sigh loudly.

Instead of installing this mod, please see the pinned comment by Shynd. It’s a much cleaner solution! But I’ll keep the mod up in case the “System.GC.ConserveMemory” configuration is not working for you.

I run an SPT-Server 4.x instance on a modest little Linux-based VServer with 4 GB of memory, bravely hosting sessions for friends and myself. Over time, I noticed that the server behaved like a dragon guarding treasure: it hoarded memory and refused to give any of it back, even when the system was gasping for air.

After some investigation, this turned out to be a quirk of .NET, not a widespread SPT issue.
And because telling .NET to stop misbehaving is roughly as effective as asking a black hole to please not eat things, I built this mod.

Its entire purpose is to force the server to clean up memory at configurable intervals (every 5 minutes by default). Each cleanup may cause a tiny lag spike — a brief hiccup in spacetime — but this is still preferable to the server collapsing in a heap after several hours of enthusiastic hoarding.

For good measure, our server also restarts every 24 hours, because at some point even a digital machine deserves a nap.

This mod is not a fix. It is a workaround, a band-aid, a polite nudge to the .NET garbage collector. If anything else on your server goes wrong, this mod should be the first thing you uninstall and the last thing you reinstall, in that order.

One more time for those at the back: Do not install this mod for performance improvements. Only use it if you are experiencing the exact memory problem described above.

To install, simply extract the .zip or .7z file into your SPT(-Server) directory.

After installation, your file structure should look like this:

C:\yourSPTfolder\SPT\user\mods\com.swiftxp.spt.servermemorycleaner\SwiftXP.SPT.ServerMemoryCleaner.Server.dll
C:\yourSPTfolder\SPT\user\mods\com.swiftxp.spt.servermemorycleaner\config\config.json

You can adjust the cleanup interval in:

C:\yourSPTfolder\SPT\user\mods\com.swiftxp.spt.servermemorycleaner\config\config.json

Additional technical details

SPT-Server 4.x is powered by the .NET Framework, a managed runtime environment that handles memory in much the same way a well-intentioned but occasionally confused robot might — automatically, efficiently, and sometimes disastrously.

Objects 85,000 bytes or larger are placed into a special area called the Large Object Heap (LOH).
The LOH is only cleaned during a full (generation 2) garbage collection, and by default it is not compacted, meaning that over time it can swell and fragment like an overstuffed suitcase.

This mod periodically instructs .NET to:

  • Perform a full garbage collection (including the LOH)
  • Compact the LOH (politely, but firmly)

The SPT team has already taken steps to make memory use more efficient, and for most users the .NET Garbage Collector does a perfectly fine job on its own. However, on our Linux-based VServer, the LOH behaves… strangely. Thus, this mod.
