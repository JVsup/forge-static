The Quartermaster

A global, player-driven second-hand marketplace.

Sell gear from your stash. Buy gear that other players have sold. Every item has a history.

You can submit and view community made contracts on my website to be added to the automatic rotating quest pool

A Living Marketplace

One of the most interesting parts of Fence in live Escape from THE CITY is that his inventory is influenced by what players sell.

SPT can’t naturally recreate that shared economy.

Until now.

The Quartermaster brings a true player-driven second-hand marketplace to SPT.

Rather than generating random stock, The Quartermaster buys equipment that real players have sold and makes it available to everyone else running the mod.

Every item you see has a history.

Someone found it.

Someone used it.

Someone decided to sell it.

Now it’s available for you.

When it’s gone, it’s gone.

Scavenging

Death in THE CITY is brutal. But it doesn’t go to waste.

When a player dies in a raid, The Quartermaster’s workers move in. They scavenge one item from the corpse and bring it back.

The item is held for a delay period before hitting the marketplace. Someone’s loss becomes someone else’s find.

Scavenged items display the profile name of the fallen player as a tag on the bottom left of the item icon - a grim reminder of where it came from. Once purchased, the tag is removed. The past is erased.

Community Reward Packages

Loyalty doesn’t go unnoticed.

Players who contribute to the community through marketplace purchases will receive weekly reward crates from The Quartermaster.

The more you spend, the better your tier. Higher tiers contain better gear - ammo, medical supplies, weapons, armour, and more.

Crates arrive via in-game mail. Open them to see what The Quartermaster has secured for you this week.

Community Contracts

The Quartermaster’s work changes over time.

Daily tasks, weekly contracts and limited-time operations can be delivered directly through the mod without requiring a new download.

Everyone running The Quartermaster receives the same active contracts, creating a shared SPT experience while keeping the game fully single-player.

Complete the job before it expires.

Miss the window, and the opportunity is gone.

You can submit and view community made contracts on my website to be added to the automatic rotating quest pool.

Requirements

  • SPT-AKI 4.0.13
  • A working internet connection

Installation

  1. Download the latest release from the SPT Hub.
  2. Extract the SPT folder into your SPT install directory.
  3. Launch the SPT server.
  4. The Quartermaster will appear in the trader list. Click Refresh on his page if his assortment is empty.

Important Notes

  • Trader assort is updated by your local server reading the mods online database every time you hit refresh, or when it auto refreshes by vanilla functions.
  • Modded items are fully compatible, you can sell modded items, if another user does not have the mod, it simply will not show for said user, if they do, it will show.
  • Items sold to the trader will stay there for a configured time in the backend (can change) before expiring and being deleted.
  • Contract data (quests, schedules, config) is fetched from a dedicated caching server every 5 minutes, reducing database load. If the caching server is unreachable, the mod falls back to reading directly from the database automatically.
  • Marketplace cleanup (removing expired and sold listings) is handled by a central server, so your local server doesn’t need to download the full marketplace data for cleanup.
  • Quest submissions go through a voting system to ensure only quality quests are auto approved (I can still override submitted quests).
  • Voting lasts for 12 hours, and requires a minimum of (5 - can change in real time in backend) votes with a 70% upvote ratio, if the minimum votes are not met, the time will be extended for another 6 hours up to 48 where it will be auto rejected.
  • If someone is seen to be submitting blatantly troll quests, your discord id will be banned from submitting any more quests.
  • New quests are added to the trader every Day/Week/Weekend, and if high quality, will be kept in the rotating pool.
  • One time quests can also be submitted, these will then be deleted after they expire (24 hours).
  • When new quests are added, you’ll receive an in-game message from The Quartermaster letting you know what’s been added.
  • When new quests are added, it requires a game restart for it to be injected into your local database.
  • Brand new quests are prioritised over quests that have already been used before, this is to ensure that it stays fresh and only repeats quests when new ones are not available.

v1.2.1 Changelog

Bug Fixes

  • Fixed mail “Get All Attachments” crash for some players - Removed manual DialogueRecords mutation in CommunityContractService that created malformed Dialogue entries. The Quartermaster contract notification now only sends the websocket popup, letting SPT’s MailSendService own the mail dialog. This prevents the client from sending an empty dialogId to /client/mail/dialog/getAllAttachments, which caused Unable to cast EmptyRequestData to GetAllAttachmentsRequestData errors when claiming reward crates.

Manual fix for affected profiles

If you cannot claim rewards:

  1. Shut down the SPT server.
  2. Open the affected profile save (SPT_Data/user/profiles/<profileId>.json).
  3. Locate dialogues and remove the entry keyed by 66789abcde1234567890abcd (The Quartermaster trader ID).
  4. In the same profile JSON, locate migrations and remove the quartermasterLastClaimedWeek key (this lets the weekly reward crate be re-sent on next start).
  5. Restart the server. The next reward/notification will recreate the Dialogue entry correctly.

v1.0.7 Changelog

Contract Notification Improvements

  • No more duplicate contract notifications - The server now persists the last seen contract version locally, so restarting the server no longer triggers a “new contracts” message unless the version has actually changed.
  • Per-contract notification tracking - The server now tracks which individual contracts have already been notified about, so players only receive messages for genuinely new contracts they haven’t seen before.

Bug Fixes

  • Fixed duplicate schedule entries - Schedule entries were being duplicated because the duplicate check only looked for active entries, not scheduled ones. The check now covers both statuses.
  • Fixed workshop sync overwriting submission status - The workshop sync was overwriting the status field on submissions, causing pending submissions to lose their voting status.

Server-Side Processing Moved to Central Server

  • Contract scheduling now handled centrally - All contract scheduling (expiring active contracts, activating scheduled ones, filling empty slots, removing duplicates) is now done by the central caching server instead of each player’s game server. This eliminates race conditions where multiple servers would create duplicate schedule entries simultaneously.
  • Submission voting now handled centrally - The voting process (approving, rejecting, extending voting periods) is now managed by the central server cron job instead of the game server. Submissions will no longer be auto-rejected by overly strict server-side validation.
  • Approved submissions auto-linked - Submissions approved manually via the admin panel are now automatically picked up and have contract definitions created for them by the central server.

v1.0.5 Changelog

This should be the last optimisation update for now and I will be looking at features/other changes from now on unless anything urgent comes up.

Marketplace Backend Overhaul

  • Marketplace data now served via caching server - Similar to last update with contracts, marketplace listings are now fetched from a dedicated caching server instead of every player’s server reading the database directly. This dramatically reduces database reads and bandwidth usage, especially during peak usage with many connected servers.
  • Automatic fallback - If the caching server is unreachable, the mod automatically falls back to reading directly from the database. You won’t notice any interruption.

FIR (Found-In-Raid) Fix

  • FIR stripping - The mod now strips the Found-In-Raid flag from all items when building the trader assortment, ensuring FIR status is never displayed on marketplace items regardless of cache state or database conditions (Due to people still using v1.0.0 which would upload items as FIR).

v1.0.4 Changelog

Contract Data Delivery

  • Faster, more reliable contract delivery - Community contracts, schedules, and backend config are now fetched from a dedicated caching server instead of each player’s server reading the database directly. This means contract data loads faster and more reliably and reduces read cost on the firebase end, especially during peak usage.
  • Still no files downloaded to your machine - The mod reads contract data in memory over HTTP, exactly like loading a web page. Nothing is written to disk.
  • Automatic fallback - If the caching server is ever unreachable, the mod automatically falls back to reading directly from the database as before. You won’t notice any interruption.

Marketplace Cleanup Improvements

  • Reduced database usage - Marketplace cleanup (removing expired and sold listings) is now handled by a central server instead of every player’s server downloading the full marketplace data every 5 minutes. This dramatically reduces bandwidth usage for all players and saves database usage.
  • Same cleanup behaviour - Expired and sold listings are still cleaned up on the same schedule. The only difference is that one server does the work instead of hundreds.

New Features

  • In-game contract notifications - When new community contracts become available, you’ll receive a message from The Quartermaster in your in-game message center letting you know what’s been added. No more checking the trader page to find out if new contracts are live.
  • Contract expiry countdown - Quest descriptions now show how long is remaining before the contract expires (e.g. “Expires in 1h 23m”). The client-side mod provides a live countdown timer on the quest page, ticking down every second in real time so you always know exactly how long you have left.

v1.0.3 Changelog

Critical Fixes

  • Fixed expired listings not being removed - A bug in how the mod communicated with the database meant expired listings were never actually marked as expired, causing them to pile up indefinitely (1000+ stale listings in some cases). Expired and sold listings are now cleaned up properly on every refresh.
  • Fixed a crash when reading the catalogue version - The marketplace version number could sometimes be stored as a number instead of text, causing the mod to crash when trying to read it. This is now handled gracefully.

Marketplace Cleanup Overhaul

  • Faster cleanup - The old system only allowed one server at a time to run cleanup, which meant with many servers running the mod, cleanup rarely actually happened. Now every server cleans up expired and sold listings during its own refresh cycle.
  • Listings removed sooner - Expired listings are now deleted in a single pass instead of requiring two separate sweeps, meaning they disappear from the marketplace faster.
  • Orphan data cleanup - Listing data left behind without a corresponding listing is now automatically detected and removed, keeping the database clean and reducing download sizes through the database.

Privacy Disclosure

  • Added a Privacy Disclosure to the mod description - A comprehensive network activity and privacy disclosure document detailing all destination servers, data transmitted, retention policies, and opt-out instructions.
