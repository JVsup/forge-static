English

A utility library extracted and optimized from various mods, specifically designed for SPT (Single Player Tarkov) server modding.

The current stable version (v1.0.0) includes core functionalities for File Size Calculation & Formatting, Internationalization (I18N), and a Modular Logging System.

Tip: For detailed code examples and implementation patterns, please refer to the SuntionCore.Tests project included in the source repository.

Key Features

1. Magnitude Formatter

A robust tool for formatting numerical values with dynamic units (e.g., KB, MB, GB).

  • Provides sealed configuration types (MagnitudeConfig) and common presets (MagnitudePreset).
  • Automatically formats numbers into readable strings based on step thresholds (e.g., 12.12 KB, 36.24 MB).

2. File Size Utilities (FileSizeUtil)

Efficient tools for handling file metrics.

  • Calculate raw file sizes in bytes via static methods or string extensions.
  • Convert file paths directly into human-readable size strings with customizable decimal precision.
  • Includes built-in exception handling for invalid paths or inaccessible files.

3. Internationalization (I18N)

A comprehensive multi-language management system.

  • Instance Management: Supports multiple independent translation contexts identified by name.
  • Dynamic Loading: Batch loads language files (xx.json) from directories.
  • Advanced Syntax:
    • Chain keys using :: for concatenated translations.
    • Parameter replacement using {{VariableName}} syntax.
  • Database Integration: Optional integration with DatabaseServer to track and utilize SPT’s native localization dictionaries (SptLocals).

4. Modular Logging (ModLogger)

A dedicated logging system designed to separate mod-specific logs from the main server output.

  • Isolation: Each mod writes to its own log file(s), preventing main log pollution.
  • Strategies: Supports single-file rotation and multi-file separation by log level (Info, Warn, Error, Debug).
  • Auto-Cleanup: Configurable file size limits to automatically purge old logs upon server startup.
  • Thread-Safe: Ensures safe concurrent access across multiple threads.

Since all the above functions of this module manage instances through static properties, you can use them anywhere

ModLogger is particularly suitable for recording debugging information that needs to be output, without having to search through the SPT logs for your own logs among other module logs.

How to Reference This Library

>= v1.2.0

Add PackageReference By NuGet

.csproj:

<ItemGroup>
    <PackageReference Include="SuntionCore" Version="x.x.x" />
</ItemGroup>

Old Version

To use SuntionCore in your own mod project:

  1. Copy DLL: Install this mod to your SPT instance, then copy SuntionCore.dll from user/mods/SuntionCore/ into a libs folder within your mod project.
  2. Update Project File: Add the following reference to your .csproj file: 
    <ItemGroup>
    <Reference Include="SuntionCore.dll">
        <HintPath>libs\SuntionCore.dll</HintPath>
        <Private>False</Private>
    </Reference>
</ItemGroup>
    Note: Ensure <Private> is set to False to prevent bundling the DLL with your mod output.

Create mod dependencies using the following code:

class YourModMetadata
{
    public override Dictionary<string, Range>? ModDependencies { get; init; } = new()
    {
        { "com.suntion.suntioncore", new Range(">=1.0.0") }
    };
}

Quick Usage Overview

String Extensions

Extend standard strings with powerful utility methods:

  • .ToFileSize(): Returns a formatted file size string (e.g., "61.23 KB").
  • .CalFileSize(): Returns the raw file size in bytes (long).
  • .Translate(): Retrieves localized text with support for key chaining and argument injection.

Workflow Examples

Formatting Numbers: Use MagnitudeFormatter to convert raw values into unit-based strings instantly.

Handling Files: Call FileSizeUtil.GetFileSize(path) to get a readable size string, or use the extension method on any path string.

Localization:

  1. Initialize with I18N.Initialize(databaseServer). (This initialization is required only if you need the I18N system to track SPT’s native translation dictionary based on the current language. Once initialized, you can access this dictionary via the SptLocals property.)
  2. Get an instance via I18N.GetOrCreateI18N("MyMod").
  3. Load JSON language packs and switch languages dynamically.
  4. Translate keys with automatic parameter substitution.

Logging:

  1. Create a logger: ModLogger.GetOrCreateLogger("MyMod").
  2. Log messages using .Info(), .Warn(), .Error(), or .Debug().
  3. Logs are automatically written to user/mods/SuntionCore/ModLogs.

中文

一个从多个模组中提取并优化的工具库，专为 SPT (单机塔科夫) 服务端模组开发设计。

当前稳定版本 (v1.0.0) 包含了 文件大小计算与格式化、国际化 (I18N) 以及 模块化日志系统 等核心功能。

提示： 如需详细的代码示例和实现模式，请参考源代码仓库中包含的 SuntionCore.Tests 项目。

主要特性

1. 量级格式化器 (Magnitude Formatter)

一个强大的工具，用于格式化带有动态单位（如 KB、MB、GB）的数值。

  • 提供密封的配置类型 (MagnitudeConfig) 和常用预设 (MagnitudePreset)。
  • 根据步进阈值自动将数字格式化为可读字符串（例如 12.12 KB, 36.24 MB）。

2. 文件大小工具 (FileSizeUtil)

处理文件指标的高效工具。

  • 通过静态方法或字符串扩展计算原始文件大小（字节）。
  • 直接将文件路径转换为人类可读的大小字符串，支持自定义小数精度。
  • 包含对无效路径或无法访问文件的内置异常处理。

3. 国际化 (I18N)

一个全面的多语言管理系统。

  • 实例管理： 支持多个由名称标识的独立翻译上下文。
  • 动态加载： 从目录批量加载语言文件 (xx.json)。
  • 高级语法：
    • 使用 :: 连接键以实现串联翻译。
    • 使用 {{VariableName}} 语法进行参数替换。
  • 数据库集成： 可选择与 DatabaseServer 集成，以跟踪和利用 SPT 的原生本地化词典 (SptLocals)。

4. 模块化日志 (ModLogger)

一个专用的日志系统，旨在将特定模组的日志与主服务器输出分离。

  • 隔离性： 每个模组写入自己的日志文件，防止主日志被污染。
  • 策略： 支持单文件轮转和按日志级别（Info, Warn, Error, Debug）分离到多文件。
  • 自动清理： 可配置文件大小限制，在服务器启动时自动清理旧日志。
  • 线程安全： 确保跨多个线程的并发访问安全。

由于本模块以上所有功能均通过静态属性管理实例，因此您可以在任何地方使用它们

ModLogger 特别适合记录需要输出的调试信息，而无需在 SPT 日志中从其他模块的日志里费力查找您自己的日志。

Version 1.1.0 Release Notes

Chore: Core Library Update

Observability Improvements: Enhanced Log Tracking and Exception Context Information

This release focuses on improving the robustness and debuggability of the core library, particularly in edge cases related to object disposal and missing localization data. No public API changes have been introduced.

  • Refactored ModLogger.LogMessage Logic

    • Improved error handling when the logger instance has been disposed (_disposed state).
    • Instead of failing silently, the system now outputs red-highlighted error logs directly via Console.WriteLine.
    • These diagnostic messages fully capture the context of the failure, including:
      • The affected stream type (LogWriterStream).
      • The original log message that was attempted.
      • The full exception stack trace (StackTrace).
    • This ensures that critical post-disposal logging attempts are always visible and traceable.

  • Refined I18N Exception Prompts

    • Enhanced the NotLoadLanguageException to provide clearer, more actionable error messages.
    • The exception now dynamically injects relevant context to distinguish between two common failure scenarios:
      1. Setting the current language: The error message now includes the CurrentLang that was being set when the failure occurred.
      2. Retrieving translation keys: The error message now specifies the missing key that the system attempted to translate.
    • This improvement significantly increases troubleshooting efficiency by immediately identifying the root cause of translation failures.
